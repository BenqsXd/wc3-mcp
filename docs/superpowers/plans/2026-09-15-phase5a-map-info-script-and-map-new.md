# Phase 5a: Map Info Script Sections and `map_new` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline; the user asked for no subagents after spend-limit failures). Steps use checkbox (`- [ ]`) syntax. Facts below were read from the 462 local JASS corpus scripts and from a map saved by the current World Editor (3.0.0.24268) on 2026-09-15; the generator rules are found and proven against the corpus during execution, test-first, as in Phase 4.

**Goal:** Every editor-generated part of `war3map.j` can be rebuilt from the map files (map info included), and a new playable map can be created from scratch with `map_new`.

**Architecture:** `wc3mcp.script.mapinfo` generates the script header comment and the Upgrades, TechTree, Players, Main Initialization and Map Configuration sections from `war3map.w3i` (plus tileset data and which other sections exist); `script.build.splice` rewrites that tail zone like the Phase 4 section zone, and `script.build.new_script` assembles a whole script from nothing. `wc3mcp.ops.newmap` writes the files the current editor writes for a new map and builds its script; `server.map_new` opens the result.

**Tech Stack:** Python 3.13 Store interpreter, stdlib only.

**Spec:** `docs/superpowers/specs/2026-09-14-wc3-mcp-design.md` (section 4 "Map lifecycle" `map_new`; section 5 script rebuild rule "players/forces"; build phase 5).

**Phase 5 split** (stacked branches, one plan each): 5a map info script + `map_new` (this plan, branch `phase5-extended`), 5b Lua script generation (`script_build` and `map_new` for Lua maps, checked against the 94 local Lua maps), 5c campaigns (`.w3n`, `war3campaign.w3f`, campaign-scope object data/imports; sample `.w3n` made with the Campaign Editor in a take-turns session because none exists locally), 5d AI (`.wai` codec on the 7 CASC samples, `ai_get`/`ai_edit`/`ai_export`), 5e assets (MDX/MDL, BLP/DDS/TGA, `asset_*`).
